# 隐藏管理器的更新与限制

NekoSU 的隐藏管理器会以随机包名和本地自签证书重新安装 Manager，
内核通过 `/data/adb/ksu/manager_identity` 记录的身份（包名 + 证书 SHA-256）
识别它。本文说明隐藏状态下的更新、备份与恢复行为。

## 用户与安装范围

- 隐藏管理器的安装、卸载、`pm path`/UID 查询以及数据目录固定使用 **user 0**。
- 如果 Manager 运行在 secondary Android 用户下，隐藏/恢复会直接拒绝并提示
  “仅支持 user 0”；本版本不改变内核的多用户身份逻辑。
- 设备存在其他 Android 用户时界面会提示：隐藏管理器只为主用户安装/恢复。

## 更新链路

1. 仅当隐藏管理器检测到 **稳定版 Release** 且 Release 附带 `SHA256SUMS`
   资产时才提供更新；没有校验和、或校验和无法读取/不包含所选 APK 时不提供更新。
2. 夜间/测试版（nightly/beta）没有 Release 签名和 `SHA256SUMS`，
   隐藏状态下禁用；界面会提示“请先恢复官方管理器再更新”，不会进入下载失败流程。
3. 下载完成后先校验 `SHA256SUMS`，再用保存的隐藏包名、图标和本地密钥
   （`identity.p12`）对官方更新 APK 重新签名，最后交给系统安装器。
4. 重签后的 APK 与当前隐藏包同名同证书，内核身份记录和 root 权限保持不变；
   安装成功后 `BuildConfig.VERSION_CODE`/`versionName` 即为新版本。

## official.apk 备份语义

- `official.apk`（用于恢复的官方 APK）在**准备隐藏更新时**就会被新官方版本替换，
  **不是**等安装完成才替换。
- 因此如果用户取消安装提示，`official.apk` 仍是新的官方版本；
  重新点击通知中的安装/重新下载更新即可重试，已准备的更新文件也可再次安装。
- 若隐藏管理器被手动升级（绕过本更新链路），保存的官方 APK 可能更旧；
  恢复流程会放宽版本校验，先安装保存的官方版本，之后可通过官方更新流程补齐，
  界面与日志会明确说明。

## 图标与名称

- 隐藏前会检测 activity-alias 自定义图标并自动切回默认图标，避免隐藏后
  仍显示旧 alias 图标；若切换失败会提示先恢复默认图标。
- 隐藏副本的名称与图标由 `ManagerAppearance` / `ManagerIcon` 在重签时写入。

## 校验和状态

隐藏管理器页面会显示当前更新源（默认仓库或自定义 `owner/repo`）
以及最近一次稳定版检查的 `SHA256SUMS` 状态：已提供、缺失、不可用或尚未检查。
自定义仓库保存在应用设置中，清空即恢复编译期默认仓库。
